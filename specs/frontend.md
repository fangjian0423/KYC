# Module Specification: Functional Case Management Dashboard Front End
# Purpose: Dashboard for listing, inspecting, uploading multi-type document images, and triggering agentic verification workflows.

[METADATA]
Target_Framework: React (Vite template with TypeScript)
Deployment_Target: Azure Container Apps (ACA)
Styling: Tailwind CSS

[UI ARCHITECTURE & INTERACTIVE LAYOUT]
The frontend is a fully functional React Single Page Application engineered with stateful tracking for file manipulation and process triggers.

1. Master View (Case Grid):
   - Renders a clean grid list displaying all active corporate cases fetched from the backend API.
   - Columns: Case ID, Company Name, Country, Created Date, System Status (Color-coded badges).
   - Interaction: Clicking a case line populates the state provider and updates the active view to the Case Detail Panel.

2. Case Detail Panel (Dynamic Stateful Workspace):
   - Left Input Column: 
     - "Document Type Selector" Dropdown: Must support selection between [PASSPORT, BUSINESS_REGISTRATION, BANK_STATEMENT].
     - "File Dropzone/Uploader Area": Standard HTML5 file area accepting image MIME types (image/jpeg, image/png). When an image file is captured, it updates the component's state array and creates a local base64 preview URL for visual confirmation.
     - "Trigger Verification System" Button: Evaluates active form data, issues a multipart/form-data or JSON base64 POST request payload containing the mapped document schema to the backend endpoint, and shows a loading spinner during agent orchestration.
   - Center Visualizer Column: 
     - Renders dual side-by-side JSON/data block visual components to expose systemic drift:
       - Card A: Document Extraction Layer -> Outputs information retrieved by the extraction vision agent.
       - Card B: Official Government Registry Data -> Outputs live corporate data mapped from the OpenAPI registry.
   - Right Intelligence Column:
     - Component block displaying the calculated Match Score (0-100 Gauge/Progress element) generated by the Foundry Comparison Agent.
     - Maps an items array rendering color-coded discrepancy highlights for conflicting values (e.g., mismatched names or skewed equity metrics).

[CONTAINERIZATION SPECIFICATION (AZURE CONTAINER APPS)]
Provide a multi-stage `Dockerfile` optimizing image payload for Azure Container Apps:
- Stage 1: Node alpine base layer executing npm build targets to output compiled static web assets.
- Stage 2: Nginx alpine distribution layer exposing port 80, reading static build outputs, and redirecting all fallback routing safely back to index.html to protect React client side routing parameters.

[REQUIRED COPILOT OUTPUTS]
1. `App.tsx` showing unified view-switching mechanics, table layouts, and state management for current case records.
2. `DocumentUploadComponent.tsx` incorporating custom dropdown values, state handlers tracking file collections, and asynchronous API integration via Axios targeting `process.env.VITE_BACKEND_API_URL`.
3. The multi-stage production `Dockerfile` matching the Azure Container Apps environment specification.
