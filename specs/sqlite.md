# Module Specification: SQLite Data Access Layer
# Purpose: Embedded, file-based state store and JSON data repository for Case Management (local dev / PoC).

[METADATA]
Target_Runtime: Node.js (TypeScript) / Express Backend
Library: better-sqlite3 (synchronous SQLite3 bindings for Node.js)
Security_Mode: PoC (local file — no network, no auth)
Default_DB_File: <cwd>/kyc.db

[DATABASE CONFIGURATION]
Table_Name: cases
Pragma: journal_mode = WAL  (safe concurrent reads, single writer)

[TABLE SCHEMA]
CREATE TABLE IF NOT EXISTS cases (
  id         TEXT PRIMARY KEY,   -- UUIDv4, matches document id
  created_at TEXT NOT NULL,      -- ISO8601 timestamp — indexed for ORDER BY
  updated_at TEXT NOT NULL,      -- ISO8601 timestamp
  data       TEXT NOT NULL       -- full Case document serialised as JSON
);
CREATE INDEX IF NOT EXISTS idx_cases_created_at ON cases(created_at DESC);

Design rationale: the Case document is polymorphic (fields are added progressively
by agents). Storing the full document as a JSON blob avoids schema migrations as
agent fields evolve. Only the columns needed for queries/ordering are materialised.

[DOCUMENT SCHEMA — stored inside `data` column]
Identical to the Cosmos DB spec schema. See cosmosdb.md [DOCUMENT SCHEMA SPECIFICATION].

{
  "id": "string (UUIDv4 generated by backend)",
  "status": "string (SUBMITTED | EXTRACTION_COMPLETE | UBO_COMPLETE | VERIFIED | DISCREPANCY_FOUND)",
  "companyName": "string",
  "countryCode": "string (ISO-2)",
  "createdAt": "string (ISO8601)",
  "updatedAt": "string (ISO8601)",
  "documents": [
    {
      "docId": "string",
      "fileName": "string",

  "extractedData?": { ... },      -- optional; added by Extraction agent

[IMPLEMENTATION FILES]
server/src/db/SqliteCaseRepository.ts   — repository class (see below)
server/src/db/repositoryFactory.ts      — selects SQLite | Cosmos | mock at startup

[REPOSITORY CLASS]
Class: SqliteCaseRepository

Internal helpers:
  - getDb(): Database.Database
      Lazily initialises the singleton Database instance.
      Reads SQLITE_PATH env var; falls back to path.join(process.cwd(), 'kyc.db').
      Runs CREATE TABLE / CREATE INDEX on first call.
      Logs: "[db] SQLite ready at <path>"

  - rowToCase(row: CaseRow): Case
      Deserialises the `data` JSON column back to a typed Case object.

Public async methods (same interface as CaseRepository / MockCaseRepository):
  - createCase(companyName, countryCode, documents): Promise<Case>
      Generates UUIDv4 id, sets status = SUBMITTED, timestamps = now.
      INSERT INTO cases (id, created_at, updated_at, data) VALUES (?, ?, ?, ?)

  - getCaseById(id): Promise<Case>
      SELECT * FROM cases WHERE id = ?
      Throws Error with statusCode = 404 if row not found.

  - updateAgentState(id, section, data, nextStatus): Promise<Case>
      Reads existing case via getCaseById, spreads new section data, advances status.
      UPDATE cases SET updated_at = ?, data = ? WHERE id = ?

  - getActiveCases(): Promise<Case[]>
      SELECT * FROM cases ORDER BY created_at DESC

[REPOSITORY FACTORY]
server/src/db/repositoryFactory.ts selects the backend at startup (after dotenv loads):

  Priority order:
  1. USE_MOCK_DB=true  → MockCaseRepository (in-memory, no persistence)
  2. COSMOS_CONNECTION_STRING set → CaseRepository (Azure Cosmos DB)
  3. (default) → SqliteCaseRepository (file-based SQLite)

  The factory is a singleton; getRepository() returns the same instance on every call.
  Handlers call getRepository() lazily inside route callbacks (not at module load time)
  so that dotenv has already populated process.env before the first call.

[ENVIRONMENT VARIABLES]
SQLITE_PATH   (optional) Absolute or relative path to the .db file.
              Default: <server cwd>/kyc.db
USE_MOCK_DB   Set to "true" to bypass SQLite and use the in-memory mock instead.

[DEPENDENCIES]
better-sqlite3   ^9.x   (native addon — requires node-gyp build tools on install)
@types/better-sqlite3   dev dependency

[DEV NOTES]
- kyc.db is created automatically on first server start; no migration tool needed.
- kyc.db should be added to .gitignore to avoid committing local test data.
- better-sqlite3 is synchronous; no await needed on DB calls internally,
  but the repository methods are declared async to keep the interface compatible
  with the Cosmos and mock implementations.
